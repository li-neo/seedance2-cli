# 典型错误与自动处理 (`error-cases.md`)

本文档总结了 `seedance2-cli` Skill 在执行过程中可能遇到的典型错误，以及脚本内置的自动化处理与兜底策略。

---

## 1. 人脸/肖像素材合规限制

- **典型错误**：
  直接使用包含清晰人脸的素材 URL (无论是公开的 `http/https` 链接还是临时的 TOS 签名链接) 调用 Seedance API 时，可能会触发平台的合规策略，导致任务失败。错误信息通常包含 `face`, `人脸`, `肖像`, `portrait`, `人像` 等关键词。

- **自动处理机制** (`pipeline.py`)：
  1.  **捕获异常**：脚本会捕获 `seedance_cli.py` 抛出的异常，并检查错误信息是否与人脸/肖像限制相关。
  2.  **触发 Assets 兜底**：如果匹配，脚本会立即启动兜底流程。
  3.  **自动上传 Assets**：调用 `assets_cli.py`，将之前生成失败时使用的**所有**素材 URL 自动上传至私域素材库（Assets）。这个过程是幂等的，如果素材已存在，会直接复用。
  4.  **替换为 Asset ID**：上传成功后，原始的 `http/https` 或 `tos://` URL 会被替换为安全的 `asset://<id>` 格式。
  5.  **自动重试**：使用替换后的 `asset://` ID 重新构建请求内容，并**再次调用** Seedance API 进行生成。

- **用户感知**：
  整个过程对用户是透明的，用户只会在控制台日志中看到类似以下的提示，而无需手动干预：
  ```
  [YYYY-MM-DD HH:MM:SS] ⚠️ 拦截到人脸审核限制: ...
  [YYYY-MM-DD HH:MM:SS] ⏳ 触发人脸/肖像限制兜底: 正在将 N 个素材上传至私域人像库...
  ...
  [YYYY-MM-DD HH:MM:SS] ⏳ 步骤 3/3: 使用入库后的资产重新请求生成视频...
  ```

## 2. 参数超出安全范围

- **典型错误**：
  用户为了追求特定效果，可能提供超出模型最佳实践范围的参数，例如请求生成一个 30 秒的视频 (`--duration 30`)。

- **自动处理机制** (`validate_and_normalize.py`)：
  - **参数裁剪 (Clipping)**：脚本不会直接拒绝请求，而是会将参数值“裁剪”到预设的安全范围内。
    - **示例**：`--duration 30` 会被自动修正为 `--duration 15`。
  - **清晰日志**：每次自动修正都会在日志中打印一条消息，明确告知用户哪个参数被修改、原值和新值是什么。
    - **示例日志**：`[参数规范化] 参数 duration=30 超出安全范围 [4, 15]，已裁剪为 15。`

- **相关参数**：
  - `--duration`: 裁剪至 `[4, 15]` 秒范围。

## 3. 输入素材不完整或组合模糊

- **典型错误**：
  - 用户只提供了一个音频文件，没有提供任何视觉参考。
  - 用户没有提供任何文本提示或媒体素材。

- **自动处理机制** (`select_mode.py`)：
  - **模式降级与告警**：脚本会选择一个最稳定、最可能产生合理结果的模式，并生成一条告警信息。
    - **示例 (纯音频)**：模式会被判定为 `multimodal_ref2v`，但会附带一条告警：“仅检测到音频参考，...建议同时提供至少一张图片或一个视频...”。最终，为了避免底层接口报错，该模式会进一步降级为 `t2v`，由用户在 Prompt 中描述音频内容。
    - **示例 (无输入)**：模式会降级为 `t2v`，并告警：“未检测到文本提示或任何参考素材，将退化为文生视频模式...”。

- **核心原则**：
  尽可能避免任务因输入不规范而直接失败，而是通过**模式降级**和**清晰告警**来引导用户或保证基础的可执行性。

## 4. 本地文件路径处理

- **场景**：
  用户在参数中提供了本地文件系统路径（如 `/path/to/my/image.png`），而不是一个 URL。

- **自动处理机制** (`pipeline.py` & `tos_cli.py`)：
  1.  **路径识别**：`is_local_file` 函数会自动识别出所有非 `http/https/asset://` 开头的路径。
  2.  **自动上传 TOS**：所有识别出的本地文件会被 `tos_cli.py` 自动上传到对象存储（TOS），并生成一个有时效性的签名 URL。
  3.  **无缝替换**：在调用生成接口前，原始的本地路径参数会被替换为新生成的 TOS URL。

- **用户感知**：
  用户无需关心文件上传的细节，只需提供本地路径即可。控制台会输出上传进度和结果。
